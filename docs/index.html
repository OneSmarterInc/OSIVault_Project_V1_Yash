Core Security Architecture

The 6 Pillars of OSIVault

A unified, enterprise-tested security suite designed for modern zero-trust backend systems.

osivault.fields

Field Encryption & SearchHash

AES-256-GCM envelope encryption for sensitive fields with fresh DEKs. Includes HMAC-SHA-256 blind indices (`SearchHash`) allowing secure SQL filtering without decrypting database columns.

  • EncryptedTextField & EncryptedJSONField
  • Deterministic SearchHash indexing
osivault.audit

Tamper-Evident Audit Trail

Merkle-linked cryptographic audit logs. Every log entry contains a signed hash derived from its predecessor. Includes PostgreSQL immutability triggers enforcing DB-level zero deletion.

  • Merkle SHA-256 hash chaining
  • PostgreSQL BEFORE DELETE triggers
osivault.sign

Digital Signature Envelopes

Self-describing signature envelopes over arbitrary bytes and JSON payloads. Supports HMAC-SHA256, RSA-PSS, and post-quantum algorithm agility wrappers.

  • Self-describing signature headers
  • Non-repudiation verification
osivault.tokens

JWKS & Token Core

RS256 JWT issue, verification, and automated key rotation with RFC 7517 JSON Web Key Sets (JWKS) publishing for seamless microservice auth verification.

  • RFC 7517 JWKS endpoint generation
  • Zero-downtime key rotation
osivault.auth

MFA & Replay Guards

RFC 6238 compliant TOTP adapters with built-in time-window replay protection and WebAuthn / FIDO2 passkey integration hooks.

  • TOTP replay window guards
  • WebAuthn / Passkey support
osivault.watch

Compliance & Audit Posture

Machine-readable security inventory and cryptographic algorithm posture reporting to ensure continuous compliance across all microservices.

  • Machine-readable posture JSON
  • Crypto algorithm deprecation watch

PostgreSQL Deep Defense

Why Database Triggers Matter

Application-level rules only protect against API requests. OSIVault PostgreSQL Triggers block direct SQL deletions in pgAdmin and DBeaver.

Layer 1: Application Level Only

Without Database Triggers

If an attacker or developer accesses pgAdmin or DBeaver directly, they can run direct SQL statements (`DELETE FROM audit_log`) and destroy audit records because Python middleware is bypassed completely!

-- Direct pgAdmin SQL Execution:
DELETE FROM audit_trail_collegeauditlog;
--> DELETE 1500 (Vulnerable: Data Lost!)
Layer 2: OSIVault Database Immutability

With OSIVault PostgreSQL Triggers

OSIVault installs a native PostgreSQL BEFORE UPDATE OR DELETE trigger directly on the database table. Even raw pgAdmin queries are blocked instantly at the SQL engine level!

-- Direct pgAdmin SQL Execution:
DELETE FROM audit_trail_collegeauditlog WHERE id = 1;
ERROR: OSIVault audit entries are immutable!
Developer Friendly

Integrate in under 5 Minutes

Clean Pythonic APIs designed for seamless Django, FastAPI, and Flask integration.

from django.db import models
from osivault.fields import EncryptedTextField, SearchHash

class StudentRecord(models.Model):
    name = models.CharField(max_length=255)
    
    # 1. AES-256-GCM Envelope Encryption at rest
    ssn_id = EncryptedTextField(blank=True, null=True)
    
    # 2. Deterministic Blind Index for SQL queries
    ssn_search_hash = models.CharField(max_length=64, db_index=True, blank=True)

    def save(self, *args, **kwargs):
        if self.ssn_id:
            self.ssn_search_hash = SearchHash(self.ssn_id)
        super().save(*args, **kwargs)
from django.db import models
from osivault.audit.models import OSIVaultAuditLog
from osivault.audit import append

class CollegeAuditLog(OSIVaultAuditLog):
    details = models.TextField(blank=True, default="")

# Automatically append Merkle audit entry on save
def audit_student_change(sender, instance, created, **kwargs):
    action = "CREATE" if created else "UPDATE"
    append(
        model_class=CollegeAuditLog,
        actor="AdminUser",
        tenant="MainCollege",
        resource_type="STUDENT",
        resource_id=str(instance.id),
        action=action,
        details=f"Updated student: {instance.name}"
    )
# settings.py
MIDDLEWARE = [
    'django.middleware.security.SecurityMiddleware',
    'django.contrib.sessions.middleware.SessionMiddleware',
    # OSIVault Immutability Middleware: Blocks HTTP PUT/PATCH/DELETE on audit URLs
    'audit_trail.middleware.OSIVaultImmutabilityMiddleware',
    'django.middleware.common.CommonMiddleware',
]
# audit_trail/apps.py
from django.apps import AppConfig

class AuditTrailConfig(AppConfig):
    name = 'audit_trail'

    def ready(self):
        import audit_trail.signals
        from osivault.audit.postgres import install_postgres_immutability_trigger
        
        # Auto-installs PostgreSQL BEFORE DELETE trigger on boot
        install_postgres_immutability_trigger('audit_trail_collegeauditlog')
